# Spec P1 — API lõi

- **Ngày:** 2026-07-18 · **Branch:** `feat/p1-api-core` · **Trạng thái:** đã triển khai (W1–W6) — D1 chốt ESM-first, chạy không cần fallback
- **Phụ lục:** [ADR-0001](../adr/0001-tech-stack.md) · [Schema audit](2026-07-18-schema-audit-nexora.md)

## 1. Mục tiêu

Dựng nền móng backend hoàn chỉnh để P2 (money-path) chỉ việc port logic:
`@tourism/api` (NestJS) chạy được end-to-end với **schema v2 đầy đủ**, **Better
Auth**, **contract oRPC đầu tiên** (catalog read), **worker pg-boss riêng**, và
**Docker hóa từ ngày đầu**.

**Ngoài phạm vi P1:** logic bookings/payments/refund (P2) · email templates
thật (P2) · web/admin/mobile · AI chat (P6) · deploy cloud (sau P2).

## 2. Quyết định mở cần chốt cùng spec

**D1 — ESM-first trên NestJS 11 (khuyến nghị ✅).** Ba dependency lõi
(`better-auth`, `pg-boss`, `@orpc/nest`) đều ESM-native; ADR-0001 đã chốt "sợi
chỉ ESM". Phương án: `"type": "module"` + tsc/SWC NodeNext ngay từ đầu — v12
(Q3) đằng nào cũng ESM, làm CJS bây giờ là tự rước lại "dynamic-import dance"
của Nexora nhân ba. **Fallback đã định trước:** nếu Nest 11 + ESM phát sinh
friction > 1 ngày công, lật về CJS + dynamic import (pattern Nexora đã chứng
minh) và quay lại ESM khi migrate v12 (chính sách 30/09).

**D2 — oRPC adoption theo D1.** Contract package (`@tourism/contract`) là Zod
thuần, không phụ thuộc framework — viết ngay. Nếu D1-ESM chạy: mount qua
`@orpc/nest` `@Implement` luôn trong P1. Nếu rơi fallback CJS: controller REST
mỏng validate bằng đúng Zod contract đó, swap sang `@Implement` khi v12 (chi
phí swap nhỏ vì P1 chỉ có ~6 endpoint).

## 3. Kiến trúc & cấu trúc

```text
apps/api/                    # NestJS 11 + Fastify adapter, Node 24, ESM (D1)
  src/main.ts                # HTTP entrypoint
  src/worker.ts              # pg-boss worker entrypoint (process RIÊNG, chung codebase)
  src/modules/...            # config · health · auth · catalog (tours/destinations/categories)
  prisma/schema.prisma       # schema v2 (§4)
  prisma/hardening-v2.sql    # CHECK + citext + RLS (port + bổ sung)
  Dockerfile                 # multi-stage, kiêm artifact deploy
libs/shared/contract/        # @tourism/contract — Zod 4 schemas + oRPC contract
compose.yaml                 # postgres:17 + api + worker (một lệnh boot cả hệ)
```

- Local dev: **Docker Postgres** trong WSL (compose service, port 5432);
  Supabase project mới = staging/prod, chỉ nhận migrate khi deploy.
- Kết nối: pool trực tiếp ~10 conn; worker dùng connection riêng.
  **Cấm transaction pooler** (CLAUDE.md).

## 4. Schema v2 (áp toàn bộ audit — tóm tắt thao tác)

1. Port 27 model từ Nexora làm gốc.
2. **Identity:** bảng Better Auth (`user/session/account/verification`, uuid PK)
   qua `@better-auth/cli generate`; merge domain fields: `phone VarChar(30)`,
   `role UserRole`, bỏ `supabaseId`/`locale`; **`deletedAt DateTime?`**
   (tombstone — bảng duy nhất có soft delete).
3. **Money:** bảng **`Refund`** mới (bookingId · amount `Decimal(14,2)` ·
   currency · providerRefundId · adminId · createdAt); bỏ 4 cột `refunded*`
   trên Booking; Booking thêm snapshot `tourTitle` + `departureStartDate/EndDate`
   - `unitPrice`; PaymentEvent thêm `amount?/currency?/bookingId?`; toàn bộ
   Decimal 12,2 → **14,2**.
4. **Review:** thêm `authorDeleted Boolean @default(false)` + index
   `[tourId, isApproved, authorDeleted, createdAt desc]`.
5. **Index theo audit M3** (thêm 6, bỏ 3, sửa 1) · `difficulty` → enum
   `TourDifficulty` · `Subscriber.email` → citext, `subscribedAt`→`createdAt` ·
   PK uuidv7 cho Review/Enquiry/EnquiryNote/Subscriber/Post.
6. **`hardening-v2.sql`**: port CHECK (seats, rating, amount ≥ 0) + citext +
   RLS (bổ sung `cancellation_requests`, `refunds`) + CHECK status↔refund mới.
7. Seed port từ Nexora (điều chỉnh theo schema mới) — có data demo ngay P1.

## 5. Better Auth (v1.6.x)

- Email/password + Google OAuth; bảng riêng của ta (Prisma adapter).
- **Tombstone flow:** `beforeDelete` hook → set `deletedAt`, scrub
  `name/phone → null`, `email → deleted+<uuid>@tombstone.local`, hard-delete
  session/account, `updateMany` bật `Review.authorDeleted`. Không hard-delete
  row user.
- Admin dual-grant giữ nguyên tinh thần Nexora: env `ADMIN_EMAILS` bootstrap
  (hook first-login promote, không bao giờ demote qua sync) + cột `role`.
- Email verify/reset: dev = console log; prod = Resend (dây sẵn, template P2).
- Nest guard: `AuthGuard` đọc BA session (thay JWT Supabase); decorator
  `@Roles('ADMIN')` như cũ.

## 6. Contract oRPC đầu tiên (`@tourism/contract`)

Phạm vi P1 — catalog read (public) + health, đủ chứng minh chuỗi type
end-to-end: `health.check` · `tours.list` (filter category/destination/search +
phân trang) · `tours.bySlug` · `destinations.list` · `categories.list`.
Zod schemas là **một nguồn sự thật**: DTO validate + response type + client
type cho P3 web sau này.

## 7. Worker pg-boss (v12)

- `src/worker.ts` boot pg-boss trên connection riêng; đăng ký queue `outbox`
  (drain skeleton — port cấu trúc `outbox.service` nhưng P1 chỉ log-deliver),
  cron giữ chỗ cho maintenance.
- **Retention từ ngày đầu** (audit M5/H6): cron xóa Outbox `SENT` > 30 ngày;
  chat retention để P6 khi có bảng chat thật sự dùng.
- Quy ước dedupeKey văn bản hóa trong `docs/` (audit M5).

## 8. Docker

- `Dockerfile` multi-stage (deps → build → runner slim); target chạy được cả
  `main.js` lẫn `worker.js` (CMD override).
- `compose.yaml`: `postgres:17-alpine` (volume) + `api` + `worker` —
  `docker compose up` là cả hệ sống, phục vụ demo/báo cáo.

## 9. Test & chất lượng

- Vitest: unit cho logic thuần (contract schemas, tombstone scrub, admin
  grant); integration cho Prisma flows chạy trên Docker PG (db test riêng,
  `migrate deploy` + truncate giữa test).
- Port dần test liên quan từ Nexora khi port module tương ứng.
- Gate: `pnpm gate` + CI hiện có (bổ sung service postgres cho job integration).
