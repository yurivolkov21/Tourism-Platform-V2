Account area

Five screens, redrawn. The account area is a travel notebook, not a dashboard — every page answers one question and none of them holds much, so structure and whitespace do the work that charts and stat rows would do wrong. Same Wuling tokens, same three faces, same 63 primitives as the booking flow.

Screen 4 · /account/profile

Profile

Read mode by default. A page of grey inputs waiting to be typed into looks like an unfinished form; a summary list with a Change link on each row looks like a card that is already filled in — which is the truth, and it is what people come here to check.

Read mode · one row opened Only the row being changed becomes a form, with its own Save. Email is read-only with a reason, not silently disabled. Danger zone closes the page — no separate route, no thick red box.

Screen 5 · /account/saved

Saved tours

The same card the catalogue uses, not a special one — two production code bases converged on that, and it means a saved tour looks like the thing you saved. No folders: Booking.com measured 1.8% of bookings coming from wishlists, which does not buy five modals and a sharing model.

Saved grid Removing happens in place with an X in the corner — not a heart. A heart on the saved page is ambiguous: it looks like it might add something. The heart belongs on the catalogue card, which is cluster B's job.

Notes

What to check

Decisions made in this round, and the debts it pays.

Cards stop dissolving in the dark

Page and card sit 1.13:1 apart in dark, and the token border on a card is 1.45:1 — cards were vanishing. Fixed without inventing a token: structure prefers one sheet with hairline rows over floating cards, and real card edges use a border mixed with 22% foreground — 1.45 → 2.36 dark, 1.96 → 2.94 light. Heavy shadow was tried and rejected: on a dark ground it reads as murk, not lift.

Status reads as English, not as an enum

"Paid", "Awaiting payment", "Cancelled" — the labels already in @tourism/i18n, one source shared by all three screens. The monospace face goes back to what the brief assigns it: the booking reference. The five-word vocabulary is still fixed; it just isn't shouted in SCREAMING_SNAKE_CASE.

Debts this pays

  • A1 — the whole area redrawn off the temporary build.
  • A2 — the cancellation reason box exists, so the request stops sending a hardcoded string.
  • A3 — the dark contrast debt, closed by the card treatment above.

Space held for cluster B

Two dashed slots mark what cluster B will fill: the review form on a booking, and the heart on the catalogue card. Drawn rather than left blank so nobody reads them as an oversight — and so the layout around them is already settled when the spec lands.

What the list deliberately can't show

bookings.mine returns cancellationStatus: null for every row on purpose, to avoid an N+1. So a booking awaiting a cancellation decision looks ordinary in the list, and one quiet line says so rather than pretending otherwise.

Five screens, not six

/account/security is a 308 redirect to the profile, not a page — it exists for route parity with the old product. Nothing to design there.
